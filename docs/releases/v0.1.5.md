# viewr 0.1.5

A patch release over [v0.1.4](v0.1.4.md). It stops a malformed JPEG XL file from
terminating the viewer, makes a folder on the command line open the way the help
text already promised, settles the menu bar spacing, and closes the last
reliability gap in the decode executors. No feature scope changed, and the
privacy boundary is unchanged.

The **v0.2.0** reliability milestone and its exit criteria remain open; this
patch does not close them.

## Fixed

- **A malformed JPEG XL file can no longer terminate the viewer.** viewr
  composites each frame channel by clipping its region against the output
  region. A hostile stream could clip a channel to zero area, and the decoder
  then borrowed a zero-width buffer and panicked. Release builds abort on panic
  and JPEG XL decodes in process, so opening one such file ended viewr rather
  than reporting that the image could not be decoded. Compositing an empty
  region is now skipped, which is what it already meant. The exact input is kept
  as a fuzz regression seed and replayed by a test on every run. viewr's own
  fuzzing gate found this before release, it was not reported in the wild, and
  no other format is affected.
- **A folder handed to viewr from outside the window opens that folder.**
  `viewr help` documents that a folder opens its first naturally sorted image,
  and the empty-state card offers Open Folder, but a folder passed on the
  command line reached the decoder instead of the folder scan and reported that
  the image source must be a regular file. The path is now classified once, and
  a directory starts the same browse the Open Folder button starts. Every
  channel that delivers a bare path shares that decision: the command line, a
  drop on the window, a desktop Open With, and the macOS open-file event. A path
  that does not exist is still opened as a file, so the error keeps naming the
  missing file rather than reporting a folder you never asked for.
- **The menu bar reads as one bar.** The five menu titles sat 22 logical pixels
  apart, which reads as five separate controls. Titles now carry 8 points of
  padding on each side and nothing between them, so they sit about 16 pixels
  apart and neighboring highlights meet instead of leaving a dead seam for a
  pointer crossing an open menu bar. The reading strip on the right keeps its
  own 8px gaps.

## Changed

- **A decode worker that dies is reported instead of waited on.** Each
  replace-latest decode queue now closes when its last worker stops, including a
  worker that unwinds. Before this, only the image preview queue did. A worker
  lost on the foreground decode or current-image details queue left its queue
  accepting work that no thread would ever run, so the operation stayed busy
  with nothing to report and no error: the details queue has a single worker, so
  one failure was enough to leave ratings and image facts waiting forever.
  Scheduling now fails with a named message the viewer shows. A queue served by
  several workers still survives losing one of them. Release builds continue not
  to claim general recovery from an in-process thread panic; the affected
  operation reports the loss and the interface asks for a restart.

## Install and verify

Download the archive for your platform or use the fixed-version installer
command in the [installation guide](../INSTALL.md). Every archive and installer
script has a SHA-256 sidecar and a GitHub build-provenance attestation. Archives
also contain a canonical per-file manifest.

The application itself has no network client. Installer scripts are separate,
foreground tools that contact only the official GitHub repository after you run
them. Updates are manual and explicit.

On Linux, a desktop session needs `libxkbcommon` plus either the X11 keyboard
and Xlib libraries or `libwayland-client`, and one usable graphics runtime:
`libEGL.so.1` for OpenGL, including Mesa software rendering, or `libvulkan.so.1`
with a driver installed behind it. `viewr doctor` reports exactly which of these
are missing and what to install.

## Preview limits

These portable archives are not Authenticode-signed on Windows or notarized on
macOS. Normal operating-system trust warnings may appear. Do not disable
platform security controls to force a launch.

The remaining 1.0 gates are unchanged by this patch: code signing and
notarization, human Narrator, VoiceOver, and Orca acceptance,
representative-hardware checks, and per-display color correctness. Optional
AVIF, HEIC, and RAW decoders are not enabled in these default archives.
