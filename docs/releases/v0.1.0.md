# viewr 0.1.0

The first public preview of viewr is a fast, focused desktop image viewer for
Windows, macOS, and Linux. It opens local photos without an account, cloud
library, telemetry, advertising, subscription, background index, or automatic
update check.

## Highlights

- Fast folder navigation with bounded neighbor prefetch and last-good-frame
  presentation.
- Broad pure-Rust format support, including JPEG, PNG, GIF, WebP, TIFF, SVG,
  JPEG XL, OpenEXR, and common bitmap formats.
- Embedded 0-to-5 XMP ratings with folder filters, no catalog, and no sidecars.
- GPU pan, zoom, fit, rotation, crop, bounded Spot Heal, Save As, and conversion.
- Presence-only source-privacy details and metadata-stripped exports by default.
- System Trash with exact-receipt Undo where the operating system can prove it.
- System, Light, Dark, and Console appearances with independent image backgrounds.
- Native menus, dialogs, keyboard controls, and AccessKit accessibility semantics.

## Security and release trust

- Hostile JPEG XL ICC tag counts and ranges fail as decode errors instead of
  terminating the viewer.
- Optional decode helpers resolve only from an explicit valid path or the exact
  binary installed beside viewr, never from `PATH` fallback.
- The runtime-reachable `event-listener` dependency includes the 5.4.2 fix for
  `RUSTSEC-2026-0221`, and CI rejects every unreviewed advisory warning.
- Installer commands execute immutable release assets, and the release workflow
  verifies the exact asset set before creating provenance for every file.

## Install and verify

Download the archive for your platform or use the fixed-version installer command
in the [installation guide](../INSTALL.md). Every archive and installer script has
a SHA-256 sidecar and GitHub build-provenance attestation. Archives also contain a
canonical per-file manifest.

The application itself has no network client. Installer scripts are separate,
foreground tools that contact only the official GitHub repository after you run
them. Updates are manual and explicit.

## Preview limits

These portable archives are not Authenticode-signed on Windows or notarized on
macOS. Normal operating-system trust warnings may appear. Do not disable platform
security controls to force a launch.

The remaining 1.0 gates are code signing and notarization, human Narrator,
VoiceOver, and Orca acceptance, representative-hardware checks, and per-display
color correctness. Optional AVIF, HEIC, and RAW decoders are not enabled in these
default archives.

## Known issues in this release

Found by first-contact testing of the published archives. The release is
immutable, so these are fixed on `main` and ship in the next tag. The
workarounds below apply to the v0.1.0 archives as published.

- **Linux, X11: the first launch aborts when `libxkbcommon-x11` is absent.** The
  windowing backend loads that library at run time, so `ldd bin/viewr` does not
  list it and `viewr doctor` did not check it. The launch ends in a loader panic
  naming `libxkbcommon-x11.so`. Install the package for your distribution
  (`libxkbcommon-x11-0` on Debian and Ubuntu, `libxkbcommon-x11` on Fedora, RHEL,
  and Arch). The [installation guide](../INSTALL.md) now lists every runtime
  library per session type.
- **A failed GPU surface exits 0 with no message.** When the session cannot
  create a surface, v0.1.0 logs the reason only under `RUST_LOG=viewr=debug` and
  exits successfully, so `viewr photo.jpg` looks like a no-op. Run
  `RUST_LOG=viewr=debug viewr <path>` to see the reason, and install working GPU
  drivers or the Mesa software renderer.
- **`viewr doctor` reports a healthy install on a host that cannot open a
  window.** Its checks cover binaries, worker IPC, privacy, and decoding, not
  window presentation.
- **`--help` is not reserved on subcommands.** In v0.1.0, `viewr doctor --help`
  runs doctor, `viewr benchmark --help` fails with `not a directory`, and
  `viewr open --help` treats the flag as a path. Use `viewr help` for the
  command list.
- **An unknown word is treated as an image path**, so a mistyped command starts
  the GUI instead of reporting the typo.
- **`viewr-decode` run by hand waits forever.** It is the decode worker and
  expects a binary protocol on standard input. Press Ctrl+C; nothing was
  started or written.
