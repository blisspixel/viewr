# viewr 0.3.0

The display-correct SDR milestone. Tagged source color matches published
reference conversions, unmanaged Windows-legacy and real X11 convert working
sRGB into the admitted display ICC, and moving the window between those
displays updates the picture without a restart. A first-open decode failure
no longer claims a previous image is visible when the canvas is empty.

This closes the **v0.3.0** exit criteria. The **v0.4.0** file-coherence
milestone is the next gate and remains open. Wide-gamut and HDR stay off.

## Fixed

- **A first-open decode failure tells the truth.** An independent playtest of
  the published v0.2.0 Linux archive found the toast claiming the previous
  image remained visible when nothing was on the canvas. The previous-image
  clause is now used only when a picture is actually presented. Retry stays
  available either way.

## Color

- **Unmanaged displays receive the admitted ICC.** Windows with Advanced Color
  off reads the ICM profile for the monitor that owns the window. Real X11
  reads the root-window `_ICC_PROFILE` atom. Those paths convert working sRGB
  into the display encoding at GPU upload. Export, edits, and thumbnails stay
  in working sRGB.
- **A monitor move updates the picture.** Changing display identity rebuilds
  the transform and re-uploads the current image. Windows Advanced Color is
  queried again so Auto Color Management stays compositor-managed. Wayland,
  Xwayland, macOS, and Windows ACM keep tagged sRGB and do not apply a second
  transform.
- **Image Information is honest.** The swapchain is reported as
  operating-system managed, as a display profile applied, or as the
  deterministic sRGB fallback. Unmanaged X11 without an admitted profile uses
  the fallback rather than claiming compositor management.
- **Reference vectors stay independent of the library.** sRGB, Display P3, and
  Adobe RGB display destinations are derived from the published matrices and
  transfer functions. A wrong matrix or transfer function moves saturated
  colors by tens of code values against a one-value tolerance.

## Install and verify

Download the archive for your platform or use the fixed-version installer
command in the [installation guide](../INSTALL.md). Every archive and installer
script has a SHA-256 sidecar and a GitHub build-provenance attestation. Archives
also contain a canonical per-file manifest.

The application itself has no network client. Installer scripts are separate,
foreground tools that contact only the official GitHub repository after you run
them. Updates are manual and explicit.

On Linux, a desktop session needs `libxkbcommon` plus either the X11 keyboard
and Xlib libraries or `libwayland-client`, and one usable graphics runtime:
`libEGL.so.1` for OpenGL, including Mesa software rendering, or `libvulkan.so.1`
with a driver installed behind it. `viewr doctor` reports exactly which of these
are missing and what to install.

## Preview limits

These portable archives are not Authenticode-signed on Windows or notarized on
macOS. Normal operating-system trust warnings may appear. Do not disable
platform security controls to force a launch.

Reaching this milestone does not shorten the remaining 1.0 gates: file
coherence, format contracts, product quality, code signing and notarization,
and human Narrator, VoiceOver, and Orca acceptance. Wide-gamut preservation
and HDR presentation stay off. Release builds still do not claim general
recovery from an in-process thread panic. Optional AVIF, HEIC, and RAW
decoders are not enabled in these default archives.
