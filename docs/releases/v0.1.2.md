# viewr 0.1.2

A patch release over [v0.1.1](v0.1.1.md). It finishes the launch-diagnosis work
that release started: viewr now chooses its own windowing backend, and it names
the graphics runtime a host is actually missing instead of a package that is
already installed. No feature scope changed, and the privacy boundary is
unchanged.

The **v0.2.0** reliability milestone and its exit criteria remain open; this
patch does not close them.

## Fixed

- **A leftover `WAYLAND_DISPLAY` no longer blocks a working X11 session.** viewr
  resolves the backend itself: a Wayland variable whose compositor socket does
  not exist is not a session, so the X server named by `DISPLAY` runs instead.
  The event loop is pinned to that resolution, so `viewr doctor` and the launch
  path can no longer disagree about which backend runs.
- **An event loop that refuses to start reports one packaged sentence.**
  v0.1.1 printed the dependency's own error, which embeds the source path of the
  machine that built viewr. The reason is kept and the build path is dropped.
- **GPU advice stopped recommending a package that is already installed.** viewr
  renders through Vulkan or OpenGL, and its OpenGL backend reaches Mesa through
  EGL, so `libgl1-mesa-dri` alone never fixed a failed surface. The message now
  separates two different hosts: one with no graphics runtime at all, which gets
  the `libEGL` and Vulkan package names per distribution, and one that has a
  runtime and still cannot present, which is pointed at the session rather than
  at another install command.
- **`viewr doctor` reports both graphics runtimes.** A desktop session with
  neither EGL nor Vulkan cannot create a GPU surface, so that is now a critical
  failure with the package to install. Headless hosts skip these lines and stay
  green, so installers and CI keep working.
- **A passing `doctor` no longer reads as proof that the viewer works.** Its last
  line states that no window was opened and names the command that proves one.

## Documentation

- The [installation guide](../INSTALL.md) lists the graphics runtimes viewr
  renders through, with the package per distribution, and corrects the earlier
  claim that Mesa's DRI drivers alone are enough. It also documents the
  stale-`WAYLAND_DISPLAY` rule.
- The decode worker is described as printing a short explanation rather than one
  line, matching what it prints.

## Install and verify

Download the archive for your platform or use the fixed-version installer
command in the [installation guide](../INSTALL.md). Every archive and installer
script has a SHA-256 sidecar and a GitHub build-provenance attestation. Archives
also contain a canonical per-file manifest.

The application itself has no network client. Installer scripts are separate,
foreground tools that contact only the official GitHub repository after you run
them. Updates are manual and explicit.

On Linux, a desktop session needs `libxkbcommon` plus either the X11 keyboard
and Xlib libraries or `libwayland-client`, and one of `libEGL.so.1` or
`libvulkan.so.1` with a driver behind it. `viewr doctor` reports exactly which
of these are missing and what to install.

## Preview limits

These portable archives are not Authenticode-signed on Windows or notarized on
macOS. Normal operating-system trust warnings may appear. Do not disable
platform security controls to force a launch.

The remaining 1.0 gates are unchanged by this patch: code signing and
notarization, human Narrator, VoiceOver, and Orca acceptance,
representative-hardware checks, and per-display color correctness. Optional
AVIF, HEIC, and RAW decoders are not enabled in these default archives.
