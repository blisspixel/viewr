# viewr 0.1.4

A patch release over [v0.1.3](v0.1.3.md). It fixes a first window that could not
fit the screen it opened on. No feature scope changed, and the privacy boundary
is unchanged.

The **v0.2.0** reliability milestone and its exit criteria remain open; this
patch does not close them.

## Fixed

- **The first window fits the monitor it opens on.** viewr asked for the same
  1000 by 720 logical window on every display. A desktop reserves space no
  process can query through winit, so on a small screen with a taskbar, dock, or
  panel that request was granted and the window was then placed with its lower
  edge behind the furniture: the folder-preview rail and the buttons on the
  empty-state card could not be read or clicked, and resizing did not recover
  them until the window was moved first. The requested size is now bounded by the
  monitor, at most 90 percent of its logical width and 70 percent of its height,
  and never below the 640 by 480 minimum viewr already enforced. The window is
  also placed 5 percent of the monitor height below its top edge and centered
  across, because desktop furniture is not symmetric: a dock, taskbar, or panel
  almost always takes the bottom of the screen, so the bottom fifth is left to
  the desktop rather than split around the window. Displays with room for the
  preferred size keep it, loading an image still never resizes the window, and
  Wayland, which does not accept client placement, still gets the bounded size.

## Changed

- The typed error set is measured by the coverage floor instead of excluded from
  it, and every launch category it reports has a direct test. The remaining
  whole-file exclusions are exactly the native integration surfaces: the winit
  event loop, the wgpu device, the worker sandbox and its process limits, and the
  two binary entry points.

## Install and verify

Download the archive for your platform or use the fixed-version installer
command in the [installation guide](../INSTALL.md). Every archive and installer
script has a SHA-256 sidecar and a GitHub build-provenance attestation. Archives
also contain a canonical per-file manifest.

The application itself has no network client. Installer scripts are separate,
foreground tools that contact only the official GitHub repository after you run
them. Updates are manual and explicit.

On Linux, a desktop session needs `libxkbcommon` plus either the X11 keyboard
and Xlib libraries or `libwayland-client`, and one usable graphics runtime:
`libEGL.so.1` for OpenGL, including Mesa software rendering, or `libvulkan.so.1`
with a driver installed behind it. `viewr doctor` reports exactly which of these
are missing and what to install.

## Preview limits

These portable archives are not Authenticode-signed on Windows or notarized on
macOS. Normal operating-system trust warnings may appear. Do not disable
platform security controls to force a launch.

The remaining 1.0 gates are unchanged by this patch: code signing and
notarization, human Narrator, VoiceOver, and Orca acceptance,
representative-hardware checks, and per-display color correctness. Optional
AVIF, HEIC, and RAW decoders are not enabled in these default archives.
